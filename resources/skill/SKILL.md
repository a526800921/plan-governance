# Plan Governance

用计划、证据和适用验证管理跨阶段、会漂移的工作。普通一次性 bugfix、小范围本地修改和互不依赖的待办，不启用完整治理，除非已有计划覆盖或用户明确要求。

## 先分流

| 信号 | 分数 |
|---|---:|
| 跨阶段、里程碑或多轮会话 | 1 |
| 架构、公共 API、Schema、兼容性或迁移 | 1 |
| 依赖真实运行报告、样本或反馈 | 1 |
| 多计划依赖、替代、重叠或冲突 | 1 |
| 同一模块后续反复修改 | 1 |

>=3 启用/更新治理；=2 先检查已有治理再判断是否需要结构；<=1 按普通任务。大型公共契约迁移可直接启用。不为小修改强制建立计划、spec 或 ADR。

## 按需读取

| 当前工作 | 读取 |
|---|---|
| 需求探索与 grilling、制定/更新计划、文档职责或同步 | [planning](references/planning.md) 的相关章节 |
| 当前阶段准入、风险分流、自验/独立复核、验证、反馈或完成 | [verification](references/verification.md) 的相关章节 |
| 初始化/升级、检查/workset、hook、快照、图谱或分发 | [cli](references/cli.md) 的对应操作 |

参考相对本 skill 实际安装位置读取，不相对项目 cwd。仅安装 CLI 时，`plan-governance-cli guide` 读取本入口，`guide planning|verification|cli` 读取相应正文；缺失资源明确报错，不猜路径或自动安装。选择同一版本来源，不能混读不同副本；旧 CLI 不支持 guide 或风险策略时，先说明能力缺失。

## 执行底线

- 首次接手读取 PLAN_MAP、当前计划和确实相关的契约/ADR/migration；恢复先看当前工作集、当前阶段、最近证据和实际 diff，缺失或冲突再扩大读取，不每轮重读全部历史。
- 复用已确认需求和授权。未明确且满足触发条件的高影响取舍才做 grilling；可验证的事实自己查。必需回答不能以沉默推定，清楚的普通细节自主决定。
- 普通改动自验；高风险或高影响改动同一范围只独立复核一次，发现由实施者修复并自验，不再送审。范围、记录及旧策略兼容见 verification。
- 只实施已授权且准入的当前阶段，保留 Step 0、完成与失败边界。旧计划采用新策略须显式记录，迁移不抹除实际问题。
- 需要独立复核且授权明确时自动安排一名独立只读 subagent；不可用或超时不冒充已检查，未解决问题不记完成。复核不代替外部授权。
- 验证真实可观察结果，按变更范围补验；只有当前树、依赖/配置、环境和验收契约均被可信证据覆盖时才复用全量结果。纯落档做适用文档检查，不无理由全跑。
- 适用功能计划技术完成待用户体验时保持实施中，明确待验收项；用户接受后关闭。原范围小问题自主闭环，沉默、提交和技术通过不代替用户接受；普通小改不增加逐次签收。
- 状态、阶段、关系、阻塞和证据入口以 PLAN_MAP 为准；专项计划写本次差异及证据，现行契约优先复用已有 Schema/OpenAPI，按需才建 spec。新事实不写回旧草案。

已授权的 `goal` 可用于跨轮继续；本 skill 不另建整计划自主执行运行时，也不默认创建 goal、安装或发布。结束简报结果、适用验证、剩余阻塞及可访问证据，不堆完整日志。
