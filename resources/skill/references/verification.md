# 验证、复核与用户验收

本页是风险分流、阶段门和证据闭环的规范来源。[入口](../SKILL.md)先判断是否需要治理；仅 CLI 环境用 `plan-governance-cli guide verification`。

## 按风险复核

普通改动由实施者自验。只有实际高风险或高影响改动才独立复核，例如改变权限、安全、隐私、资金、数据完整性、核心契约或产生广泛/难以撤销的后果；不按目录、行数或阶段事件触发。风险不清时先补事实与验证。

同一交付范围只独立复核一次，不做前后双审。通常在实现和自验收敛后、交付或高影响外部动作前检查；治理阶段需要设计准入时将这一次前置，后续实施与完成由实施者自验。范围内的诊断、增量和修复合并处理，不把每个问题拆成新范围；确有新增需求或新的高风险影响时，仅对新增范围重新判断。

独立者一次给出发现与依据；实施者修复后验证原问题及受影响回归，记录“发现 → 修复 → 自验结果”，不再送审，包括原高风险范围内的修复。未解决的问题保持未完成，不能将自验写成独立通过。复核不可用、超时或证据失效时直接记录该状态，不写成“未通过：业务发现”；明确的“未通过”等缺陷结论及实际查出的证据冲突代表已完成检查，可修复后自验。业务缺陷中的“超时”等词不改变检查状态。

需要检查且授权明确时，自动安排一名未参与实现或测试编写的只读复核者。提供交付范围、实际差异、风险与证据入口，不复制全部聊天；检查期间冻结受审范围，变化及时告知。独立复核不替代外部操作授权。普通同步、落档及未变化的有效结论不再派复核。

## 记录与兼容

新模板使用 `复核策略：单次独立复核`。旧 `风险分流` 保留原“低风险自验、独立失败须独立恢复”语义；缺省策略仍按旧独立格式读取，空值/未知/重复不放行。已有授权时可显式改为单次策略并保留历史，不要求为切换策略先重审；迁移本身不解决任何实际问题，不批量改其他项目。

单次策略沿用下方八列记录，风险可为 `低风险`、`高风险`、`高影响`、`待判断`。高风险/高影响自验必须有本阶段同一范围的完整独立检查基线；普通低风险自验无需独立基线。独立失败后使用类型 `修复自验`、方式 `自验` 追加结果，证据包含原发现、修复差异和验证，不能以普通“自验通过”掩盖未解决发现。检查器只核对记录结构与顺序，不证明范围、独立性或证据真实性。

迁移旧独立格式时，以最新阶段表替换摘要引用，将适用的原检查按原日期、结论、证据及真实复核者转写为八列独立基线，说明范围及风险；保留旧历史与旧结论，再追加实际修复自验。旧记录冲突、缺字段或比修复更新的失败不能被迁移掩盖。新范围不能复用不覆盖它的旧基线。新会话复用已保存策略，旧 CLI 不支持新策略时说明能力缺口，更新按授权处理。

## Step 0 与阶段门

阶段 N 完成只关闭 N，N+1 默认设计中。每个当前阶段自身必须有目标/范围/非目标、可观察 Step 0、输入与可执行命令/预期/失败判定/输出位置的样本矩阵、验证与完成条件、失败/回滚边界、无未解决阻塞，以及适用复核通过，才可待实施。机器检查只核对结构，不证明实现、风险分类、证据真实性或用户接受。

| 任务 | Step 0 |
|---|---|
| 缺陷修复 | 失败回归或最小复现 |
| 迁移 | 现状快照、兼容样本或契约测试 |
| 新项目 | 可执行验收 fixture、协议样本或提交图 |
| 架构探索 | 最小原型、风险实验或关键假设验证 |

不适合固定样本时记录原因和可观察的替代基线。不要在开始实现后倒填通过证据。

### 旧计划兼容

摘要没有 `复核策略` 字段时，保留原独立门禁：固定 `阶段路线图`、`当前阶段`、`阶段准入摘要`、`最新独立准入复核`、`独立复核记录` 标题；摘要字段是 `准入状态、Step 0、样本矩阵、验证方式、失败/回滚边界、当前阻塞项、最新独立准入复核`。最新表含日期、阶段、结论、证据、复核者，当前阶段最新结论须明确通过并达到待实施标准，历史追加记录保持一致。标题不带阶段编号；地图提供阶段身份。

### 新计划风险策略

显式策略在当前阶段摘要以 `最新阶段复核` 链接替代旧最新独立字段，其余基础字段保持；旧 `风险分流` 与单次策略共用以下格式。

`最新阶段复核` 固定键值表：

| 字段 | 要求 |
|---|---|
| 日期 / 阶段 | YYYY-MM-DD / 与地图当前阶段一致 |
| 方式 | 自验或独立 |
| 风险 | 低风险、高影响或待判断；单次策略也接受高风险，待判断不能通过；自验边界见上文 |
| 风险依据 | 实际范围、后果/可逆性、验证充分性的具体依据；非占位 |
| 结论 | 尚未进行或实际结果；有效通过必须明确通过，不能以空值、失败、不可用、超时、证据冲突代替 |
| 证据 / 复核者 | 可复验命令/结果或其可访问链接，以及真实执行者身份；自验不假称独立 |

以 `通过 / 未通过` 等尚未选择结果的模板候选开头时，其后无论是问号、其他标点或待选说明，都属于未知，不能成为独立失败的恢复证据。结论以明确前缀声明当前结果，支持 `通过。` 等常见句末符号；`通过：已修复证据冲突` 可以通过，不因提到历史问题重判失败。无明确通过的不可用/超时/证据冲突仍为失败。实际未解决事项必须留在结构化阻塞中，通过说明不能覆盖它；机器不验证自由说明的真实性。

`阶段复核记录` 使用 `日期、类型、阶段、方式、风险、结论、证据、复核者` 八列表追加记录。最新当前阶段记录与最新表的日期、方式、风险、结论、证据和身份一致。单次策略允许有基线及证据的修复自验解除发现；旧风险分流仍须独立通过恢复。上一阶段历史不自动阻断当前阶段。

普通无计划小改不建立这些表。可将验证命令和结果放进现有记录，通过证据列链接，避免第二份事实源。未完成的设计模板不是准入证明；不生成已通过占位。

默认 check 对新准入缺陷 WARNING；待实施/实施中在 `--strict-readiness` 下 ERROR。workset 沿用 JSON schema 1 和既有动作：待自验 `verify`、高影响待独立 `independent_review`、有效通过但地图仍设计中 `sync`；失败 `blocked/resolve_blocker`，结构歧义 `unknown/unknown`，不自动写状态。hook 只提示。

## 验证、修复与证据复用

先验证用户可观察结果和受影响回归；验证范围依据变更及项目要求，不为字数、字段或与实现重复的断言新增无价值测试。纯文档做适用检查并注明代码覆盖率不适用；代码变更遵循项目要求和有意义的覆盖证据。

可信全量证据只有覆盖当前实际工作树、依赖、配置、环境和验证契约，且内容可访问时才可复用。HEAD/版本相同不充分；缺失、相关变化或冲突时补验。复核者核对身份并复验关键风险，不因复用报告省略独立判断。明确过时的证据记录为当前阻塞。

范围快照是可选补充；`workset` 不自动核对文件 hash 或环境变化。采用 attestation 时按 [CLI 说明](cli.md) 显式运行 `check --check-attestations --strict-readiness`，不能声称所有准入都已检查证据漂移。

自验失败由实施者修复并复验。独立发现的修复按上文单次规则处理，保留原发现并准确记录自验结果；验证范围聚焦原问题和受影响回归，不无理由重跑整套历史。当前交付与后续事项分清，记录同步不另开检查。

验证后仅追加状态/证据或修正文档链接时，做适用文档检查即可；契约、源、依赖或环境又变则补受影响验证。区分仓库源与安装版本、旧缺陷与新回归、当前范围与其他并行任务失败；如实报告全仓失败，不能用局部通过掩盖，也不擅自接管无关任务。

## 用户可观察验收与交付

验收关联到场景、输入/前置、操作、可观察结果和证据；CLI 输出/文件差异/调用方行为同样可观察，不强求界面或资源采样。需要性能验收时沿用探索确定的可比环境、负载和窗口；未实际测量不得宣称性能改善。

采用用户最终体验闭环的功能计划：AI 先技术和运行验证，提供可复验结果；技术完成但待用户查看/操作时保持 `实施中`，最近记录注明待验收项，结构化 `下一动作：等待用户验收`。workset 返回已有 `none` 并明确等待原因，不关闭计划。用户明确接受后才已完成；技术通过、提交请求或沉默都不是产品接受。普通小改、纯落档不增加逐次签收。

原验收未满足或原范围小问题自主修复/复验并交付结果；新需求或实质取舍另行归属，需用户才能提供的验收结果保持待答，可继续不依赖它的授权工作。

交接简报结果、阻塞、验证命令及范围/环境、可访问证据入口和下一动作即可；不粘贴完整日志，不为每次动作新建报告。仅工具 ID 无法被接手者访问时，提供实际要点和复验命令。对减负效果用少量同完成条件任务比较必要读取、全量验证/复核次数和实耗；保留质量反例。没有可靠宿主统计不估算 token 占比，文件字节/行数或工具次数不代替 token 和耗时。
