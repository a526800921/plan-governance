# 验证、复核与用户验收

本页维护有效策略、阶段门和交付证据；CLI 入口为 `guide verification`。执行方法按当前策略决定，写入记录时再读格式部分。

## 记录与兼容

先读取当前阶段摘要的 `复核策略`，后续复用，不由新会话或新版 skill 自动改变：

| 策略 | 行为 |
|---|---|
| 单次独立复核 | 新模板默认；普通改动自验，高风险或高影响同范围独立检查一次，修复自验 |
| 风险分流 | 旧策略；低风险自验，高影响独立，独立失败须独立通过恢复 |
| 无字段 | 保留旧独立门禁及六列记录，见旧计划兼容 |

空值、未知值和重复声明不能放行。有迁移授权时可显式采用单次策略并保留历史，不为切换先重审，迁移也不解决实际问题。迁移旧格式时替换摘要引用，将适用原检查按真实日期、结论、证据和身份转写成八列基线，说明范围/风险，再追加实际修复自验。旧记录冲突、缺字段或比修复更新的失败保留；不批量改其他项目。CLI 能力不符时说明缺口，更新按授权处理。

## 按风险复核

以下执行方式适用于单次策略；普通无计划任务也按实际风险选择检查，不建立阶段表。

普通改动由实施者自验。改变权限、安全、隐私、资金、数据完整性、核心契约或产生广泛/难以撤销后果时，按实际高风险或高影响安排独立检查；不按目录、行数或阶段事件触发。风险不清先查事实。

同一交付范围只检查一次，通常在实现和自验收敛后、交付或高影响外部动作前；需要设计准入时将这一次前置，后续实施与完成自验。已审范围内的增量和修复合并处理，确有新增高风险范围才另行判断，不把每个修复拆成新范围。

授权明确时自动安排一名未参与实现或测试编写的只读复核者，提供范围、差异、风险和证据入口。冻结受审范围并告知变化。独立者给出发现后，实施者修复并验证原问题及受影响回归，不再送审，未解决则保持未完成。检查不可用/超时直接记录状态，不能伪填已完成结论；业务缺陷描述中的“超时”不代表检查未完成。复核不代替外部授权。

## Step 0 与阶段门

当前阶段达到待实施，需要目标与范围、可观察 Step 0、可执行样本或替代基线、验证与完成条件、失败/回滚边界、无未解决阻塞及适用复核。样本说明输入、命令、预期结果、失败判定和输出位置。上阶段通过不替代本阶段准入；普通小改不新建整套治理。

Step 0 可采用缺陷复现、迁移快照/兼容样本、新功能验收 fixture 或关键假设实验；不适合固定样本时说明可观察替代方案，不在实施后倒填通过证据。

## 验证、修复与证据复用

验证用户可观察结果和受影响回归，完成项目要求的检查。纯文档做适用文档检查并注明覆盖率不适用。检查通过后，只有新变化、失败或未解疑点才扩大或重复验证。

复用证据须覆盖当前工作树、依赖/配置、环境和验收契约，内容可访问；仅 HEAD/版本相同不足以证明有效。缺口补受影响验证，未解决冲突如实保留。只有状态、证据或链接同步时，不重新跑代码全套；无关任务失败如实报告，不擅自接管。

自验失败自主修复/复验。单次策略下保留独立发现，按“发现 → 修复 → 验证”闭环并准确标记自验；旧策略的恢复要求见策略表。机械检查只证明结构，不能证明风险、范围、独立性或证据真实性。可选 attestation 的显式检查见 [CLI](cli.md#初始化模板和检查脚本)。

## 用户可观察验收与交付

用场景、输入/操作、可见结果与证据说明完成；CLI 输出、文件差异和调用方行为也可作为验收。性能结论要有可比实测，不能用字符数或工具次数推算 token、耗时或质量改善。

明确采用用户体验闭环的功能计划，技术完成待用户查看时保持 `实施中`，结构化 `下一动作` 填 `等待用户验收`；用户接受后才关闭，技术通过、提交或沉默不代替接受。普通小改、纯落档不增加逐次签收。原范围问题自主修复，新需求另行归属；等待用户才能提供的结果时可继续无依赖工作。

交付简报完成结果、必要验证、剩余阻塞及证据入口，不复制完整日志。资料不可访问时补可复验要点；记录同步不再安排复核。

## 格式附录：写入阶段记录时读取

### 新计划风险策略

显式策略在摘要以 `最新阶段复核` 引用替代旧 `最新独立准入复核`，其余阶段字段保留。最新表采用两列字段/内容：

| 字段 | 要求 |
|---|---|
| 日期 / 阶段 | YYYY-MM-DD / 与地图当前阶段一致 |
| 方式 / 风险 | 自验或独立；低风险、高影响或待判断，单次策略另支持高风险 |
| 风险依据 | 当前实际范围、后果与验证依据 |
| 结论 | 尚未进行或明确结果；待判断风险不能通过，候选、疑问或占位不算通过 |
| 证据 / 复核者 | 可复验记录或链接 / 真实执行者身份 |

`阶段复核记录` 按 `日期、类型、阶段、方式、风险、结论、证据、复核者` 八列追加，日期顺序和最新表与当前阶段末条一致。完整结果须有有效日期、证据、身份及已判断风险；普通无计划任务无需建表。

单次策略的高风险/高影响自验须有本阶段同范围完整独立基线。独立发现修复后用类型 `修复自验`、方式 `自验` 追加，证据说明原发现与修复回归，不能以普通自验覆盖未修复发现。自验不伪称独立通过。旧风险分流自验仅限低风险；旧独立失败按原策略恢复。上一阶段历史不自动阻断当前阶段。

结论以明确前缀记录：`通过`、`未通过`等；复核入口不可用/超时直接写其状态，实际查出的证据冲突可作为发现。通过说明不能覆盖结构化未解决事项。check 默认对新准入缺陷 WARNING，待实施/实施中在 `--strict-readiness` 下 ERROR。workset 保持 schema 1：待自验 `verify`、待独立 `independent_review`、通过待地图同步 `sync`、失败 `blocked/resolve_blocker`、歧义 `unknown/unknown`；不自动写状态，hook 只提示。

### 旧计划兼容

没有策略字段时，保留固定标题 `阶段路线图`、`当前阶段`、`阶段准入摘要`、`最新独立准入复核`、`独立复核记录`。摘要字段为准入状态、Step 0、样本矩阵、验证方式、失败/回滚边界、当前阻塞项及最新独立准入复核。最新表含日期、阶段、结论、证据、复核者；历史使用日期、类型、阶段、结论、证据、复核者六列，当前阶段最新结论须独立通过且与历史一致。标题不加阶段编号，阶段身份以地图为准。
