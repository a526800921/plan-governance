# 计划与契约

从 [skill 入口](../SKILL.md) 判断任务是否需要治理；仅 CLI 环境用 `plan-governance-cli guide overview`。本页只维护文档、探索与同步规则；阶段证据和复核见 [verification](verification.md)。

## 需求探索与 grilling

对可能进入治理的任务，如果运行环境声明 `grill-me` 可用，满足下列任一条件时自动调用它，在实施或冻结详细方案前先澄清需求：

1. 涉及公共 API、Schema、迁移、兼容性或不可逆操作，且目标、边界、验收或关键取舍中至少一项未明确；
2. 下列不确定性信号中至少两项同时存在：目标/验收不清、范围/非目标不清、存在多个有实质取舍的方案、关键事实尚待查证、后续返工成本显著。

目标、影响范围和验收方式均明确的小范围任务，以及当前阶段已通过准入且已确认假设没有变化的工作，跳过自动 grilling；用户仍可显式调用它。已确认的范围、验收与授权直接复用，不为相同结论重新 grilling。仅影响可选细节的问题可在合理等待后声明假设继续；必需答案和授权不可由沉默推定。

grilling 每次只问一个问题。可从仓库、环境或工具确认的事实必须先查证；产品取舍、外部承诺和不可逆选择由用户确认。结束前必须汇总并得到用户确认：目标、范围和非目标、已确认事实、暂定假设及验证方式、候选方案与取舍、未决问题及阻塞级别，以及验收口径或下一步动作。

用户确认后，只有在任务需要治理时，才把结构化结论写入专项计划的 `需求探索` 章节；不保存完整访谈逐字稿，不自动创建 ADR。探索结论不替代当前阶段的 Step 0、样本矩阵、验证方式、失败/回滚边界或适用阶段准入复核。`grill-me` 不可用时，说明依赖不可用并保持在澄清/设计边界，不得伪造已完成 grilling 或静默实施。

收敛时固定少量可观察场景：输入/前置、操作、可见结果；已有场景直接链接。涉及运行资源影响时明确环境、负载、采样窗口和相关 CPU/内存/磁盘等指标，不发明通用阈值。交互或方案明显不确定时安排关键流程原型/早期体验；目标明确的小修改不增加中途签收。反馈未到可继续不依赖它的已授权工作。

## 仓库模型

使用项目内这些文件作为事实来源：

```text
docs/
  PLAN_MAP.md
  plans/
    <plan-name>.md
  specs/
    <capability>.md        # 按需，优先复用已有 Schema/OpenAPI
  adr/
    0001-<decision>.md
  migrations/
    <migration-name>.md
```

只创建有真实内容的文件，不预建空目录或强制 PRD/design/tasks 组合。`docs/plans/*.md` 保持平铺。`docs/reviews/` 存独立复核，`docs/fixtures/` 存人工样本/回放说明，`tests/fixtures/` 存可执行输入，`docs/attestations/` 仅在使用快照时需要。

文档权责：

- `PLAN_MAP.md`：计划索引、状态、当前阶段、最后更新、依赖、替代/合并/废弃关系、推荐顺序、当前阻塞项、证据链接。
- `docs/plans/*.md`：本次变更的目标、范围、行为差异、阶段、Step 0、验证与完成条件；链接现行契约。没有独立契约来源时明确由计划哪个位置承载，不要求追溯提取旧内容。
- `docs/adr/*.md`：持久架构决策及其后果。
- `docs/migrations/*.md`：兼容策略、迁移步骤、回滚方式、旧行为保留窗口。
- 现行契约优先复用已有 Schema/OpenAPI。需要跨迭代维护文字行为且无合适来源时，才按需建立 `docs/specs/<capability>.md`；可使用 [spec 模板](../assets/spec.template.md)，补充输入/输出、不变量、失败语义与可观察场景，不复制已有字段定义或计划进度。

同一事实只定义一次，其他地方通过链接引用。独立 migration 承载迁移步骤、窗口和回滚后，计划改为引用；ADR 保留选择理由和后果，不复制契约字段或进度。

## 多文档同步规则

- 专项计划按上述文档权责记录本次差异和证据，现行字段与行为从唯一契约来源读取。
- `PLAN_MAP.md` 是状态、当前阶段、最后更新、依赖、替代/合并/废弃关系、推荐顺序、阻塞项和证据链接的事实源。
- 总路线图、优先级计划和索引只记录顺序、状态摘要和专项计划链接，不复制字段级方案、枚举、Step 0 细节或完成定义。
- 当专项计划的状态、当前阶段、最后更新、字段方案、完成条件或验证结果变化时，必须同步 `PLAN_MAP.md` 和所有引用该计划的路线图、优先级计划或索引。
- 验收治理文档时，必须用 `rg` 搜索同名计划、P 编号、状态名和关键字段，检查是否存在重复定义或漂移。
- 如果同一事实在多个文档中重复，保留一个事实源，其他文档改为链接引用。
- 实施者填写的计划状态、完成证据文字和文档格式只代表实施声明，不等于验收结论；按适用复核方式基于当前仓库内容、可复现验证命令和反向引用确认。

## 草案和历史文档处理

启用计划治理后，已有草案、历史设计、归档计划、superpowers 记录、临时分析文档等默认只作为背景材料，不再作为规范事实源。

- 除非用户明确点名要求更新这些文档，否则不要继续修改它们来承载新规范。
- 新发生的目标、范围、非目标、公共契约、字段、Schema、状态语义、阶段、验证方式、完成条件、风险和回滚，应写入 `docs/plans/*.md`、ADR、migration 或正式 spec。
- 计划状态、当前阶段、最后更新、依赖、替代/合并/废弃关系、推荐顺序、阻塞项和证据链接，应写入或同步 `docs/PLAN_MAP.md`。
- 历史草案可以在治理文档中作为背景材料链接引用，但不应承载新的规范事实。
- 如果治理文档出现“以草案为事实源”“详见草案中的字段定义”“草案为准”等表述，应改为由治理文档自身承载事实源，或链接到正式 spec/Schema。
- 当用户说“补充一下”“记录一下”“把刚才的结论写进去”时，如果治理已启用，默认写入治理文档；不要写入草案、README 或历史设计文档，除非用户明确点名该文件。

## 推荐状态

统一使用中文状态：

| 状态 | 含义 |
|---|---|
| `候选` | 记录了想法，但尚未承诺实施 |
| `设计中` | 正在明确范围、契约和门禁 |
| `待实施` | 当前阶段门禁已通过，但尚未开始 |
| `实施中` | 当前阶段推进中；适用时包含技术完成待用户验收 |
| `已完成` | 实现、验证、证据和文档齐全，并满足适用的用户验收 |
| `已替代` | 被另一个计划取代 |
| `已合并` | 并入另一个计划 |
| `已废弃` | 明确不再推进 |


## 漂移检查

当决策、实现发现或运行报告改变以下内容时，暂停实施并更新治理文档：

- 既有 ADR 或核心原则
- 计划顺序、依赖、替代关系或有效性
- 公共 API、Schema、状态语义、兼容承诺或失败模式
- 多个计划共享的重复修改点
- 用来证明完成的测试或完成条件
- 专项计划与路线图、优先级计划或索引之间的状态、字段方案、完成条件或验证结果

## 停滞检查

`PLAN_MAP.md` 的计划索引应包含 `最后更新` 列，日期格式为 `YYYY-MM-DD`。

计划索引必须在同一个 `## 计划索引` 章节下，按固定顺序拆成三张六列表格：`### 未完成`、`### 已完成`、`### 已废弃`。状态归类规则如下：

- `未完成`：`候选`、`设计中`、`待实施`、`实施中`。
- `已完成`：`已完成`。
- `已废弃`：`已废弃`、`已替代`、`已合并`等不再推进的终态；表格标题不改变行内真实状态。

每个计划只能出现一次；没有对应计划的分类保留表头但不添加占位行。必须使用三级标题，以便治理 CLI 将三张表作为同一个计划索引读取。

推荐表头：

```markdown
| 计划 | 状态 | 当前阶段 | 最后更新 | 依赖 | 证据 |
```

规则：

- `最后更新` 是显式治理元数据，不从 Git 历史或文件 mtime 推断。
- 当计划状态、当前阶段、阻塞项、依赖、完成条件、验证结果或实施范围变化时，同步 `最后更新`。
- `--stale-days` 只对 `候选`、`设计中`、`待实施`、`实施中` 等活跃计划输出 `WARNING`，不自动改变状态。
- `--stale-days` 省略数值时默认 10 天，可显式传入 N。

## 执行与恢复

首次接手读取 PLAN_MAP、当前计划和确实相关的 ADR/migration/spec。恢复时先用已有当前工作集、当前阶段、最近实施/验证记录和实际 diff 定位进度；只有缺失、冲突或相关范围变化时再展开旧资料。历史会话和全部计划不是每轮必读材料。规则与当前证据入口应可访问；只有不可检索的输出 ID 时先补真实内容或可复验入口。

先确认当前阶段准入和授权，再实施。假设、公共契约、兼容、范围、完成条件或依赖变化时，先更新唯一事实源和地图，再评估准入；阶段内原范围反馈追加差异和验证，不自动新开计划或重开所有门。原验收预期从原场景读取，不因新边界输入自行发明业务规则。

治理文档变更后做适用链接、结构、反向引用和 `plan-governance-cli check .`；用 `rg` 搜索同名计划、P 编号、状态/关键字段，以及 `草案为准|以草案为事实源|详见草案|draft is source|source of truth.*draft|以.*draft.*为准`。纯落档不重跑已有效覆盖的全部代码测试；规范行为变化仍需验证受影响场景。
