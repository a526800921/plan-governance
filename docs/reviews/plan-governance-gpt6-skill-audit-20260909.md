# GPT-6 skill 提示审查（2026-09-09）

用户目标：减少规则冲突、提高自主性，让 GPT-6 更好地完成交付。本次审查对象为提交 `c9da6e1` 的仓库 skill、三份 references、计划模板及 AGENTS 入口；本机已安装 1.0.3 仅用于识别来源差异。本次是现行提示的静态审查和有界行为推演，未改生效规则、实现或安装资源；不是又一次独立阶段门禁，也未测量模型耗时或成功率。

结论：值得继续精简。主要负担来自强制确认、宽泛暂停条件和多个版本的规则解释，单纯压缩字数不足以解决。保留治理的事实源和验证契约，把选择执行方法的空间还给模型。

## 官方依据

已检索并实际打开 OpenAI 的 GPT-6 Astra 官方指南，未用其他模型的提示指南替代：它提醒该模型更容易受到 skill/AGENTS 指令影响，并建议明确用户指令相对 skill 的优先级、复用已有授权、持续完成任务，以及只在有新变化或疑点时扩大验证。[GPT-6 Astra：Prompting best practices](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)

官方 skill 文档强调任务聚焦、清晰的触发边界、按需加载和触发测试；被选中的 SKILL.md 会完整加载，references 可承担可选细节。[Build skills](https://learn.chatgpt.com/docs/build-skills)

以上是审查标准，不意味着 OpenAI 要求本项目使用单次复核、取消阶段门或采用下列具体结构。下面的取舍是根据本项目约束作出的建议；用户明确的“新需求先文档化、实现需授权”与适用用户验收要求继续有效。

## 发现与建议

### A1 高优先：自主性原则被强制访谈收口限制

位置：[SKILL.md](../../resources/skill/SKILL.md) 第 35 行；[planning](../../resources/skill/references/planning.md#需求探索与-grilling) 第 7—16 行。

入口允许普通细节自主决定，但正文要求访谈结束前必须汇总多类内容并再次取得确认，还规定 grill-me 不可用时停在澄清/设计边界。入口没有清楚说明用户指令优先于 skill 的流程建议。这会使模型把“某项信息尚未填完整”理解为“不能继续已授权工作”。缺少访谈技能也可能成为与真实任务无关的阻塞。

建议：由具体缺口是否影响交付、授权或难以撤销的结果决定是否提问；能查证的先查，普通可逆细节自主决定。仅询问必须由用户决定且上下文未回答的内容。grill-me 作为需要深入探索时的可选方法，不作为完成任务的前提；已有决定不重复签收。明确用户指令优先于 skill 内的工作流建议，同时遵守实际权限边界。

### A2 高优先：常规证据更新也落入“暂停实施”

位置：[planning：漂移检查](../../resources/skill/references/planning.md#漂移检查) 第 88—95 行，对照同文件第 128 行及 [verification](../../resources/skill/references/verification.md#验证修复与证据复用) 第 73 行。

漂移列表同时包括核心契约变化、验证结果和状态变化，并统一要求暂停。另一处又允许阶段内反馈追加差异、纯证据同步适用自查。一次普通测试由失败变通过也会改变验证结果，文本没有在暂停条件中区分这种更新和实质边界变化，容易产生不必要的停顿。

建议：只有授权、目标、关键契约或高影响后果变化时，重新判断受影响部分；普通实现反馈及证据更新在当前任务内完成并批量同步。不能把“同步文档”自动解释为“重新取得许可”，无依赖的已授权工作可继续。

### A3 高优先：新旧策略和规则来源的选择晚于执行指令

位置：[SKILL.md](../../resources/skill/SKILL.md) 第 30、36—38 行；[verification：记录与兼容](../../resources/skill/references/verification.md#记录与兼容) 第 17—21 行；[AGENTS](../../AGENTS.md) 第 13、19 行。

入口直接说单次复核、修复自验，正文稍后又要求旧风险分流保留独立恢复。两者可以通过策略字段解释，但依赖模型主动找到例外。本仓库另有真实来源差异：AGENTS 优先引导读取已安装 skill，而新规则仍在仓库、安装版尚未同步。已保存的新策略可能因此遇到旧规则解释。

建议：开始处理时一次确定当前任务的有效策略和规范来源，其余步骤只按这一份规则执行；历史兼容仅在读取旧计划时展开。开发本 skill 时显式采用仓库源，使用发布版时采用安装资源，避免每轮重新比较。更新安装版属于后续已授权范围的操作，审查本身不自动安装或迁移。保留历史和真实阻塞，不靠删兼容文字改变检查器行为。

### A4 中优先：关键词和分数容易把普通任务吸入治理

位置：[SKILL.md](../../resources/skill/SKILL.md) 第 3、12—20 行。

描述同时覆盖架构、API、迁移、长期任务、证据、ADR 等大量信号；评分还将多轮会话、运行反馈和同模块反复修改累计为启用条件。比如一项需要几轮日志反馈的小 bugfix，可以累计三个信号，同时又属于入口说的普通小修复，分流结果不够直观。这是静态冲突风险，尚未测出实际误触发率。

建议：优先判断是否已有相关计划，或当前工作是否确实需要持久记录阶段、依赖和跨轮决策。移除数值打分；描述前置核心用途和普通任务排除条件，不把出现某个技术名词等同于需要治理。用少量正反请求检查隐式触发，而不是只检查描述中有没有关键词。

### A5 中优先：行为原则与格式细节重复加载

位置：[SKILL.md](../../resources/skill/SKILL.md) 第 34、39—41 行；[planning](../../resources/skill/references/planning.md) 的文档权责、多文档同步、草案处理及恢复；[verification](../../resources/skill/references/verification.md) 的恢复与验收；[cli](../../resources/skill/references/cli.md#当前工作集)。

当前入口为 1,692 字符，planning 4,693，verification 3,818，CLI 6,039。入口本身不算长；如果一次规划兼验证读入入口和前两份参考，已有 10,203 字符，其中事实源、少读历史、授权复用和验收边界多处重复。已经存在按需加载结构，应进一步改善内容分工，不能说所有引用文件每次都会加载。

建议：入口保留任务目的、自主执行默认、真正暂停条件、交付要求和链接；planning 只维护计划决策，verification 只维护验证与完成，CLI 只在实际操作时读。机器固定表头、兼容字段和命令参数放进按需格式段落/模板，以单一事实源引用；不另造一套更长的反例和禁止清单。长度只作辅助指标，不把字符数当 token 或性能结果。

### A6 中优先：模板仍引导无条件补覆盖率报告

位置：[计划模板](../../resources/skill/assets/plan.template.md#测试覆盖率) 第 110—112 行，对照 [verification](../../resources/skill/references/verification.md#验证修复与证据复用) 第 65 行。

模板要求完成后记录覆盖率报告，验证规范却允许纯文档说明不适用。模型在填模板时可能为消除占位内容而运行无关测试。只读调用 `has_coverage_evidence` 已确认“本次纯文档变更，代码覆盖率不适用。”被检查器接受，因此这个提示矛盾首先可以通过模板修正，未发现必须修改检查器的理由。

建议：模板写明按项目契约与实际改动提供验证，纯文档可记不适用。保留真实项目要求的检查；适用检查通过后，只有新变化、失败或未解疑点才扩大验证。不要把“有验证证据”等同于“每次都跑完整测试和覆盖率”。

## 推荐的入口方向

以下为可审阅的提示候选，尚未替换现行 skill；具体机器格式继续由 references 和模板承担：

> 帮助用户完成需要跨阶段、跨会话或协调依赖的工作，并维护足够的计划与验证证据。普通一次性任务直接处理。
>
> 根据当前请求、上下文和已有授权持续推进。用户指令优先于本 skill 的流程建议。能自行查证或作可逆决定的事项自主处理；只有缺失信息会实质改变结果或超出授权时才询问，并继续不依赖该答案的工作。
>
> 已有计划只读取当前相关阶段、差异和证据，沿用已确认目标与有效策略。实质边界变化时调整受影响计划；日常进展随工作同步。
>
> 按实际风险验证。在单次策略下，高风险或高影响范围独立检查一次，发现由实施者修复自验。真实未解决问题如实保留，检查通过后完成交付。
>
> 交付说明完成结果、必要证据和剩余问题；明确约定需要用户体验验收时保留该步骤。按当前动作读取规划、验证或 CLI 参考。

该候选不要求另建计划、增加确认节点或取消用户已经确定的单次复核规则。优先处理 A1—A3，再合并重复提示与模板不一致；机器契约保持，若后续确实改变其语义再有界调整实现。
