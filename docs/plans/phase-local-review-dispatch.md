# 计划：phase-local-review-dispatch

## 背景

当前 `plan-governance` 的跨轮持续推进由 Codex `goal` 承载；旧的“自主连续执行”计划已经废弃。现有阶段准入规则要求当前阶段在进入 `待实施` 前必须有独立准入复核，但没有规定执行者在小阶段到达该门禁时可以自动派发复核者。阶段关系、当前工作集和证据状态沿用已完成的 [plan-governance-operability-optimization](plan-governance-operability-optimization.md) 计划。

因此，计划执行会在一个通常不需要用户决策的小阶段停下来等待独立复核。这个停顿把“需要独立判断”误表现成“需要用户确认”，降低了连续推进体验；但直接恢复旧的整计划自主执行又会重新引入已废弃的执行模式，并可能越过高影响决策边界。

本计划只处理“阶段内独立复核的调度与恢复”这一局部问题：普通、目标明确且不涉及高影响决策的阶段，执行者应自动启动独立只读复核 subagent 或等价复核者，复核通过后继续推进；高影响事项、复核失败、复核不可用或证据冲突仍必须停下并报告。

## 目标

- 为阶段内独立准入复核建立“自动派发、复核返回、继续或阻塞”的执行契约。
- 让普通且目标明确的阶段在等待独立复核时不再无谓等待用户。
- 保留独立复核的真实性：实施者不能自我批准，复核必须基于当前仓库、可复现命令和阶段完成条件。
- 明确必须询问用户的高影响边界、复核失败策略、复核不可用策略和恢复条件。
- 与现有 `goal` 跨轮持续推进、阶段准入、`PLAN_MAP.md` 和历史计划兼容，不恢复旧的整计划自主执行入口。

## 非目标

- 不恢复或复活已废弃的整计划自主执行历史计划。
- 不新增 `等待独立准入复核` 计划生命周期状态；现有 `设计中`、`待实施`、`实施中` 等状态保持不变。
- 不自动批准独立复核，不把治理检查、全量测试或实施者声明当作复核结论。
- 不自动替用户决定范围、产品取舍、外部授权、凭证、公开暴露、破坏性操作、安全或隐私边界。
- 不构建通用工作流引擎，不自动执行未在当前计划和授权范围内的外部操作。

## 需求探索

### 已确认事实

- 之前确认的目标是“整个计划连续执行”，当前实际卡点收窄为“计划内部的小阶段在等待独立准入复核时无谓停止”。
- 对普通、目标清楚且不需要用户作高影响决策的小阶段，通常没有必要停下来等待用户确认。
- 遇到独立准入复核时，可以由执行者自行启动独立只读 subagent 或等价复核者；该复核不能由实施者自己批准。
- 独立复核通过后应继续当前计划推进；复核未通过、不可用或证据冲突时，应保留阻塞并报告，而不是自行放行。
- 本计划只解决阶段内复核调度，不恢复旧的整计划自主执行模型。

### 暂定假设与验证方式

- 当前 Codex 会话暴露了可创建新上下文只读 subagent、等待结果和处理异步返回的能力；这只证明当前宿主具备一次复核调用能力，不证明仓库已有计划执行 runtime 或所有宿主都支持同一入口。分发规则保持宿主无关，其他宿主在阶段 2 做能力探测和回放。
- “独立”采用程序性边界：复核任务使用独立上下文，不参与当前阶段实施，不修改工作区，并单独执行检查命令；这不等同于组织或合规意义上的第三方审批。
- 阶段内复核的完成结果由复核报告和计划记录承载；不把复核进行中增加为 `PLAN_MAP.md` 的生命周期状态。通过普通阶段、复核通过、复核未通过、复核不可用和高影响决策五类场景验证。
- 当前仓库没有计划执行 runtime 的实现代码；阶段 1 只固化宿主无关的规则入口，具体宿主调度入口和可回放运行 fixture 由阶段 2 验证。

### 范围与非目标

本计划范围是阶段准入门禁触发后的复核任务派发、独立性约束、结果消费、失败/不可用处理和继续推进边界。范围包括需要同步的 skill、代理运行说明、计划模板或复核记录字段，以及对应的测试和验证 fixture。

不在范围内的是重新设计计划生命周期、恢复 `plan next` 或步骤清单入口、建立多人审批流、自动通过高影响门禁、替代 Codex `goal`，以及对历史计划做全量回填。

### 候选方案与取舍

| 方案 | 处理方式 | 取舍 |
|---|---|---|
| A | 保持当前行为，所有独立复核都停下来等用户 | 最安全但延续无谓停顿，不符合已确认的连续推进目标 |
| B | 增加 `等待独立准入复核` 生命周期状态 | 可读性较强，但扩大状态机并违背现有“不新增计划状态”边界 |
| C | 阶段门触发时自动派发独立只读 subagent，结果通过后继续 | 推荐；解决实际卡点，保留独立门禁和高影响停机边界 |
| D | 恢复旧的整计划自主执行机制 | 范围过大，和现有 `goal` 及废弃记录冲突，拒绝采用 |

### 用户确认的探索结论

2026-09-05，用户确认：此前的“整个计划连续执行”不是当前需要恢复的能力；当前问题是计划内部小阶段会因独立准入复核而停止，而通常不需要用户确认。对于普通、目标明确且无高影响决策的小阶段，应尽可能继续推进，并在需要独立复核时自动启动 subagent 或等价复核者；只有高影响事项、复核失败、复核不可用或证据冲突时才停下请求处理。

## 不变量

- 阶段准入仍是硬门禁；自动派发复核不等于自动放行。
- 实施者不能作为自己的独立准入复核者；复核者必须以独立上下文和只读方式重新检查当前事实。
- 复核通过后才能继续越过该阶段门；复核未通过或不可用时不得自行修改结论或假设为通过。
- 高影响决策和不可逆操作前必须保留用户确认边界；“尽可能继续”不扩大授权范围。
- `PLAN_MAP.md` 继续承载计划级状态、当前阶段、依赖、阻塞项和证据链接；不新增阶段等待状态。
- `docs/plans/*.md` 继续承载阶段实施细节、复核证据和失败/回滚边界。
- 复核报告必须能定位被审查的计划阶段、revision、命令、输出和结论；历史复核追加保留。

## 公共契约变化

本计划拟冻结以下行为契约，具体字段和宿主入口在阶段 0/1 验证后确定：

```text
阶段内当前动作需要独立准入复核
    ├─ 无高影响决策，且复核入口可用
    │    └─ 创建独立只读复核任务
    │          ├─ 通过：记录复核证据，继续当前执行
    │          └─ 未通过：保持设计/阻塞状态，报告缺口
    ├─ 复核入口不可用或证据冲突
    │    └─ 不自我批准，保留阻塞并报告
    └─ 涉及高影响决策或不可逆操作
         └─ 先请求用户确认，再决定是否继续
```

复核任务至少需要返回：计划、阶段、被审查 revision、复核范围、实际执行命令、证据位置、结论、阻塞项和复核者标识。复核任务不修改工作区；主执行者只负责消费和落档该结果，不能改写“未通过”为“通过”。

复核入口不可用时，只有满足同等独立性和证据要求的等价复核者可以替代；没有复核者时必须停止并报告，安全替代动作本身不构成放行条件。

## 风险和回滚

### 阶段 1 风险和回滚

风险：自动继续的边界过宽，可能把需要用户决策的事项交给 subagent 自行判断。

控制：将外部授权、凭证、公开暴露、破坏性操作、安全/隐私和产品取舍列为强制停机边界；复核 subagent 只读且不能批准自身或实施者结果。

风险：subagent 不可用、超时或返回结论与仓库证据冲突，执行者为了连续性而静默放行。

控制：失败和不可用均保持阻塞并报告；只有明确的可观察替代复核满足当前计划条件时才允许继续。

回滚：阶段 1/2 发生越权、误放行、无限等待或兼容性回归时，恢复为当前“等待独立复核并报告”的保守行为；保留复核记录和失败证据，不删除历史结论。

### 阶段 2 风险和回滚

风险：目标宿主的入口、超时或异步结果语义与规则源不一致，导致阶段门错误继续或错误停机。

控制：先做只读能力探测和最小 fixture 回放；没有可复现入口或证据冲突时保持 `设计中`/阻塞，不将阶段 1 的资源测试当作宿主行为通过。

回滚：发现宿主回放越权、误放行或无限等待时，停用阶段 2 的自动继续路径，恢复为等待独立复核并报告，并保留回放输出和失败记录。
