# 计划：check 功能分层与 CLI 入参/返回值设计

## 背景

用户在 Motorcycle 项目的“查看未完成计划”会话中看到 Mini Production 阶段 3 的发布后验收阻塞导致仓库级 `check .` 返回 1，要求重新设计检查功能，并核查其他方法调用的入参和返回值。

现有 `has_current_blocker()` 特意保留默认检查的历史硬错误；不是无意引入的回归。[历史兼容契约](../20260906/iterative-governance-reliability.md#b02-输出及退出码兼容)保留这种行为。本次提案明确调整该契约，历史记录不回写。原[工作流减负计划](../20260906/plan-governance-workflow-streamlining.md)的实际使用验收继续由该计划负责。

## 目标

- 普通检查如实报告未完成工作，明确区分文档有效性与阶段可实施性。
- 严格准入保留真实阻塞，支持对目标计划及必要前置进行检查。
- 为全部公开 CLI 入口明确入参、输出、退出码和副作用，并记录源码/只读回放发现。
- 支持同一项目多计划、多会话并行；各会话围绕自己的目标计划读取和检查，按需带入前置与共享写入约束。
- 交付明确契约、兼容边界、实现和验收样本。

## 非目标

- 阶段 1 实施已获授权；不修改全局安装环境或目标业务项目。
- 不发布 npm、提交或推送本轮文件；之前已完成的发布授权不自动扩展到尚未实现的新设计。
- 不关闭业务阻塞、不修改 Motorcycle 项目计划、不执行真实交易或 App 发布。
- 不强制迁移存量计划，不把没有请求的独立复核加入流程。

## 需求探索

用户明确要求功能设计及其他调用的接口核查。默认范围为 npm CLI 的全部公开命令、直接调用的 Python/Node 入口及发布脚本参数；不逐一审查全部私有算法。阶段 0 形成下述方案；用户随后明确授权阶段 1 实施，实际结果见当前阶段。

2026-10-04 补充使用场景：项目通常多计划、多会话并行。首版仅给严格 check 增加目标范围，未覆盖 workset 与 hook 的信息投影，不足以保证每个会话获得聚焦信息。阶段 0 补齐公共 scope、会话入口和并行验收；阶段 1 已按后续用户授权实现。

## 不变量

- 地图与计划仍为唯一人工事实源，检查器只派生结果。
- 阻塞解析共享；不同入口可以调整严重级别，不能消除事实或给出错误的实施建议。
- 默认检查的 0 仅说明适用文档检查完成且没有文档硬错误；不表示所有计划可实施或可发布。
- 当前已发现问题、历史失败、用户验收与外部授权保持真实。

## 拟议功能契约

### 1. 检查事实与检查目的分开

下表描述不带 `--plan` 的全项目检查；聚焦模式的诊断归属与范围按下一节处理。

| 情况 | 普通 `check .` | `check . --strict-readiness` |
|---|---|---|
| 有效待办/业务阻塞，计划如实记录尚未完成 | WARNING；没有其他硬错误时 0 | 对待实施/实施中的检查对象为 ERROR、1 |
| 当前阶段明确复核失败、验收未完成 | WARNING，仍展示原因 | 对准入对象为 ERROR、1 |
| 候选/设计中尚未产出实现阶段材料 | 信息/提示；0 | 未指定目标时不强制未来阶段准入；仍展示状态 |
| 声明已完成却缺完成证据，或仍有明确当前阻塞/失败 | ERROR、1 | ERROR、1 |
| root 不存在、不是目录或读取必要输入失败 | ERROR、1 | ERROR、1 |
| 地图无法可信解析：重复 ID、非法状态/日期/路径、引用缺失、依赖环等 | ERROR、1 | ERROR、1 |
| 已启用阶段结构存在必填空值、当前阶段/最新记录冲突等准入缺陷 | WARNING、0 | 对准入对象为 ERROR、1 |
| 同一阻塞在地图/正文/摘要记录缺失或冲突 | 保守保留阻塞并 WARNING | 对准入对象 ERROR、1；无法归属的全局异常不得过滤放行 |
| 漂移、停滞、正文依赖漏登记、共享影响目标等建议诊断 | WARNING、0 | 保持各自契约；不把所有 WARNING 一律升级 |
| 合法目录尚未启用治理 | WARNING，`not_applicable`，0；明确没有执行计划检查 | ERROR、1，无法证明准入 |

“文档硬错误”指无法可信识别计划/读取事实或已完成声明缺乏基本证据；“准入缺陷”指未完成阶段的材料和结果尚不满足进入/完成条件。两者应由诊断类型区分，不从字符串前缀推测。

地图、未决问题、准入摘要、有效当前复核统一交给共享派生。删除 `has_current_blocker()` 的默认硬失败特殊通路，由相同诊断按检查目的分级。不得发生阻塞挪到另一个章节后退出码改变。不能只把旧 ERROR 改成 WARNING 而漏掉已完成计划的矛盾声明。

### 2. 明确查询和检查范围

拟新增 `check [root] [--strict-readiness] --plan <plan-id>`，`--plan` 可重复。普通与严格模式都可聚焦计划；工作集和 hook 使用同样的目标解析。作用域涉及当前目标、必要前置和明确相关约束，不等于只检查一个文件。

- 未传 `--plan`：check 保持全仓库文档检查；严格模式对待实施/实施中计划评估当前阶段。候选/设计中不因缺未来材料被判发布失败。
- 显式目标处于候选/设计中：普通模式允许尚未完成的设计；严格模式既然请求准入，就评估该目标当前阶段，材料不足必须失败，不能用状态标签绕过门禁。
- 目标必须是地图内唯一 ID；未知/重复请求 ID 返回参数错误 2。ID 不接受 glob、文件路径或模糊匹配。
- 前置采用明确依赖与当前目标阶段适用的 `hard_gate`，按实际来源阶段展开；`evidence`、`soft_context` 与单纯共享写入告警不自动扩大严格检查对象。
- 已完成前置校验证据与明确解除条件，不重新开启其已关闭的历史依赖链，也不要求其已完成之后的新阶段重新准入。当前直接依赖已废弃/替代计划时仍拒绝准入。来源阶段已通过、上游当前后续阶段阻塞时，只能凭显式阶段关系与证据确认前置已满足；不能盲目检查上游最新阶段，也不能猜已解除。
- 非终态前置的适用阶段尚未通过、记录冲突或解除条件不能确认，则目标失败。已废弃/已替代依赖必须先解决有效承接关系。
- 聚焦检查仍读取地图以解析唯一身份和关系；无法可信解析全局索引、重复 ID、必要输入不可读及无法归属但可能影响目标的诊断保守失败。可明确归属无关计划的正文缺陷、阻塞或局部依赖环不参与本次结果；全仓库检查仍报告它们。相关范围判断基于结构化归属与依赖闭包，不按消息字符串猜测，不通过过滤隐藏关联错误。
- 输出列出请求对象、实际展开的前置与纳入原因；不倾倒无关计划全文、最近证据或告警。共享写入与只读证据引用作为相关约束展示，不自动授权接管别人的计划。
- 选中已完成计划时仅表示其当前完成声明与机械证据满足检查，不证明新发布动作已经获准。

### 2.1 多会话聚焦与信息投影

同一 root 可以同时有会话 A 聚焦计划 A、会话 B 聚焦计划 B。聚焦由用户请求中的计划 ID/链接或已确认任务范围确定，在各自会话上下文中保存，每次 CLI 调用显式传入；不新增仓库级“当前计划”文件、共享可变焦点或全局环境变量来决定所有会话的对象。更换焦点须由本会话任务范围决定，不因为另一会话更新地图自动跳转。

CLI 无法自行知道 Codex 会话正在关注哪个计划。实施时同时更新同包 skill/入口说明，使 AI 首次识别目标后调用聚焦 workset，恢复时复用本会话的目标与最近证据。hook 的宿主桥接若能取得会话目标，显式传 `--plan`；不能取得时提示聚焦未设置，不冒称已经自动绑定。对不存在映射的宿主不自动安装桥接，也不承诺 CLI 控制 AI 的全部输入。

| 信息 | 聚焦会话接收范围 | 作用 |
|---|---|---|
| 主计划 | 当前阶段、准入、阻塞、下一动作、限量最近证据及其原文入口 | AI 的实际工作对象 |
| 必要前置 | 适用来源阶段、解除条件、相关结果/阻塞、证据入口、纳入原因 | 判定当前计划是否能够推进；默认只读，不给前置实施指令 |
| 证据关联 | 相关证据路径与适用范围，缺失/失效提示 | 复用证据；不复制关联计划的完整进度 |
| 共享写入同伴 | 冲突计划 ID、共享目标文件、已声明串行/所有权约束 | 防止多会话覆盖同一文件；不带其无关业务阻塞 |
| 全局异常 | 无法解释目标所需事实的最小诊断及来源 | 阻止错误放行；不倾倒所有无关计划告警 |
| 无关计划 | 不纳入聚焦结果 | 查询全项目时显式使用不带 plan 的 workset/check |

拟议命令：

```bash
plan-governance-cli workset . --plan plan-a --json --evidence-limit 3
plan-governance-cli check . --plan plan-a --strict-readiness
plan-governance-cli hook --root . --event session-start --plan plan-a
plan-governance-cli hook --root . --event pre-write --plan plan-a --paths src/a.swift
```

这些命令尚未实现。`--plan` 在三入口都可重复；解析规则与唯一 ID 约束共用。scope 描述信息聚焦与检查范围，不构成文件访问权限、实现授权或执行锁。

workset 的无 plan 调用仍是全项目概览，保留现有 schema 1/字段/枚举和默认输出。聚焦调用的 `plans` 仅含显式主计划；以新增、仅聚焦模式出现的 `scope` 元数据表达相关信息，包含 requested_plans、focused_phases、dependencies、evidence_links、shared_writes、global_diagnostics。前置/同伴项带计划、适用阶段、来源、相关结论与纳入原因，不放入主计划 next_action 队列。已有主计划记录形状不变；新元数据须在实现验收中检查旧消费者兼容性。

所有诊断先有结构化计划/阶段归属，再投影：不把全仓库 warnings 原样附加到聚焦结果。必要全局诊断保留，无法判定作用域时返回 unknown 并解释；不能从“没展示其他计划”推出其都已通过。

hook 的 session-start/stop 有 plan 时采用相同聚焦；pre-write/post-write 同时核对本次 paths。命中其他计划的共享范围只提示相关冲突，不把聚焦切换给同伴；路径不属于主计划声明范围则提示范围待确认，不假定其他计划授权可复用。无 plan 的 session-start 只显示精简活跃索引及“未设置聚焦”提示，不下发所有计划阻塞和整张证据表；无 plan 的 pre-write 可按 paths 提供候选，多个候选不能静默选一个；无 plan 的 stop 保留全项目检查并明确其范围。

未能确认目标时，AI 可先读取精简索引并继续无依赖工作；真正需要选择计划时才澄清，不能只根据 cwd 或“最近更新”代替会话意图。聚焦与证据限量是两个独立维度：限量不会裁剪必要依赖或清除阻塞。

### 2.2 并行变更与恢复

- 查询采用一次调用内的事实快照；在输出准入结论前核对主计划、相关前置和地图相关投影未发生变化。相关内容在读取期间变化则标为 unknown/事实已变更，严格检查返回 1，提示重读，不输出 ready。无关地图行变化不单独使聚焦结果失效。
- 恢复或发生阶段转换、修改范围变化、关系/前置证据变化时，重读当前目标和相关事实。HEAD 相同不证明并行工作树未变；输出附可核对的事实版本（相关文档内容和地图投影的摘要），不把旧查询当永久准入许可。
- 事实版本以 scope.facts_version 表达，摘要覆盖相关计划内容、阶段关系/阻塞索引和主计划地图行，不取整个地图原文 hash 使无关行变化失效；无作用域的全项目报告按全项目范围计算。该版本用于复查事实变化，不代表实现授权或永久有效的锁。
- 单会话只维护自己计划的事实与当前阶段；地图按相关行最小更新，写入前核对实际内容和其他会话 diff，不能拿旧全表覆盖新的地图。共享源文件、中央地图与发布资源仍需要单一写入者、串行合并或隔离工作树协调；聚焦输出不会自动锁文件或解决 Git 冲突。
- 同一工作树的 Git diff 可能由多个会话共同产生；检查器不能自动识别每行代码是谁改的。聚焦 drift/pre-commit 只输出可归属主计划/相关共享目标的诊断，明确归属其他计划的变更不作为本会话越界；无法归属的变更提示需核对，不能猜所有权或当作自动允许修改。
- 不引入自动派发/消息发送/计划认领调度器。发现相关前置阻塞时在主计划结果中呈现，是否跨会话沟通和接管仍按用户授权。

### 3. 输出与退出码

公开 CLI 的目标退出码统一为：`0` 适用操作成功完成，`1` 文档/准入检查失败或运行时/资源故障，`2` 命令语法、参数或不适用组合错误。帮助成功 0；被信号终止/无法启动外部运行时非零并解释原因。退出码不承载所有领域状态，领域结果必须读取输出。

普通 check 有警告时总结为“文档检查完成，有 N 项告警”，无告警才写“文档检查通过”；严格检查明确“准入检查通过/失败”。未启用治理写“未执行：当前目录未启用治理”，不能输出检查通过。文本 stderr 输出 ERROR；stdout 为结果与普通提示，WARNING 保留可见。

拟新增 check 的 `--json`：stdout 仅一个 JSON 对象，正常检查的领域错误也放在对象内；参数/启动前失败在 stderr 报告，不制造假结果。对象至少包含：

```json
{
  "schema_version": 1,
  "command": "check",
  "mode": "consistency",
  "status": "warning",
  "exit_code": 0,
  "scope": {"requested_plans": [], "evaluated_plans": [], "dependencies": []},
  "summary": {"errors": 0, "warnings": 1},
  "diagnostics": [{
    "code": "CURRENT_PHASE_BLOCKED",
    "category": "readiness",
    "severity": "warning",
    "plan": "example-plan",
    "phase": "阶段 3",
    "message": "发布后业务验收尚未完成",
    "sources": [{"path": "docs/plans/20261004/example-plan.md", "section": "未决问题"}]
  }]
}
```

`mode` 为 `consistency/readiness`；`status` 为 `passed/warning/failed/not_applicable`；category 为 `document/readiness/advisory/runtime`。scope 的 evaluated_plans 表示适用检查对象，requested_plans 表示显式焦点，空列表表示全项目；dependency 每项包含 `plan`、`phase`、`required_by`、`reason`，聚焦报告附相关约束和事实版本。诊断缺明确归属时 plan/phase 可为 null；来源不能确定时 sources 为 []，不猜路径。summary 只计本次报告范围内的去重诊断，同一事实的多来源合并展示；不同问题不因文本相似合并。

已有 workset JSON 保持 schema 1、readiness/next_action 枚举及字段。0 表示工作集成功读取/派生，不表示 ready；阻塞继续 `blocked/resolve_blocker`，歧义 `unknown/unknown`。致命根目录/地图读取失败返回 1；非致命领域诊断可在 warnings 中表达，严格模式对适用对象失败。该解释须写入帮助，不能要求调用方只看 shell 状态判断是否实施。

### 4. 全部命令的入参边界

| 命令 | 允许的主要输入 | 结果与副作用 |
|---|---|---|
| `check [root]` | root 或 `--root` 二选一；可重复 plan；strict、拟议 json；drift/pre-commit/stale/快照参数按模式显式组合 | 默认只读文档报告；strict 是准入报告；显式 `--attest` 写快照 |
| `workset [root]` | root 或 `--root`；可重复 plan；json/include-history/strict/evidence-limit | 只读 schema 1；plan 聚焦信息，evidence-limit 正整数且仅 JSON，不改变事实派生 |
| `guide [topic]` | 五个封闭主题，缺省 overview；单独 `-h/--help` | stdout Markdown；资源缺失 1、主题/参数错 2 |
| `setup` | 必选一次 target=codex；一次非空 destination；dry-run/force | 预览或同步资源，报告真实目的地、写入结果和差异冲突；不能漏值回退 |
| `init` | root；正常模式 plan/title/goal/phase/status；复制检查器/入口更新按模式 | 创建脚手架/受管入口/显式迁移；模式错误先失败，修改前预检全部目标 |
| `hook` | root、一个事件；可重复 plan；paths 仅 pre-write/post-write | 会话焦点投影及相关冲突提示；成功执行的领域提示保持非阻塞 0；参数错 2；运行失败须标明未完成检查 |
| `graph validate` | 一个 root；layer=functional/architecture | 只读图谱验证；缺外部索引的 fallback 状态明确可见 |
| `graph impact` | 一个 root；from；depth 1–10；format=text/json | 只读影响结果；未知节点是领域失败 1 |
| `graph code candidates` | 一个 root；symbol；kind=class/function；可选合法 file；format | 无候选/多候选是有效查询结果，0；指定 file 不存在/不可读失败 1 |
| `graph code impact` | 一个 root；repo/file/symbol；kind=class/function/method；depth 1–10；format | 外部查询成功才 0，缺工具/错误/非法响应 1；kind 按本轮核实的 GitNexus 帮助映射 Class/Function/Method |
| `plan impact` | 一个 root；input 的 JSON/YAML 对象；format | 层级/测试映射/定位结果；请求代码定位却不能唯一确认时 1，保留候选入口 |
| `release:npm` | patch/minor/major 或有效 SemVer；dry-run | dry-run 仅预览，实际执行有验证/版本/发布/恢复副作用；0/1/2 已符合目标分工 |

共同约束：

- 未知命令/选项、单值选项漏值/空白值/重复、多余 root、不适用参数组合返回 2；只有明确声明可重复的参数接受多次。
- CLI 参数类型/枚举非法为 2；合法路径参数指向的文件缺失、JSON/YAML 内容解析或领域 schema 错误为 1，诊断说明出错位置，不混淆两类失败。
- 需要值的选项不能吞掉下一开关；`--` 可明确终止选项解析，作为 root 或路径的特殊名字不通过漏值规则猜测。
- root 相对 cwd 解析，必须是目录；输入/证据相对路径按各命令声明的 root 解析。提供 positional root 和 `--root` 两种来源同时出现时报错，不隐式覆盖。
- 保留已公开的两个 AGENTS 更新别名，统一内部语义；only/upgrade/migration 模式拒绝不适用的 plan/title/goal/phase/status/force 等输入，而非静默忽略。默认值与用户显式传值应能区分。
- 普通 init 新脚手架仅允许候选/设计中；phase 与 checker 共用合法阶段校验。通过状态应由真实验证后更新，不从空模板生成。`--force` 只处理文件覆盖冲突，不绕过参数/状态校验。
- graph 的可选 file 是明确搜索边界，合法指定文件未找到匹配时返回 `no_candidate`，不能扩大搜索；省略 file 才搜索整个 root。文件须在 root 内、为可读普通文件；其他命令对 symlink/路径边界复用各自已公开契约，不借本次批量改变历史语义。
- `plan impact` 的 code_anchor 与候选入口共享 file/symbol/kind 校验；外部 GitNexus 响应至少校验受支持顶层类型/必要字段/错误状态，正常空结果与异常响应分开。适配器现有原始 result 保留，不假装有第二套完整业务 schema。
- stop hook 使用包内 checker，显式以 root 调用；不再依赖目标仓库复制脚本。正常领域失败仍只是提示 0，stdout/stderr 都保留；工具执行失败明确“未完成”。自动 hook 宿主是否忽略工具失败由宿主约定，不能用 0 冒充完成。
- `--attest` 是 check 的显式写入模式；拒绝与 workset/drift/pre-commit/目标计划过滤混用。绑定文件仍可重复且保留既有用途/替代/路径保护；任何当前 ERROR 均禁止所有形态的快照写入。完成/发布门用途须验证目标适用完成/准入条件，不能借默认 WARNING 绕过真实目标阻塞；合规目的的内容快照不自动声明完整阶段可实施。仅成功创建后报告快照路径，不能最终返回 1 却已经生成“完成快照”。
- setup/init 做全部参数与可预见目标冲突预检后再修改；不承诺跨文件原子事务。运行期失败报告已写/未写范围，允许按既有授权修复重试。
- 发布前验证版本是有效 SemVer，并核对目标是否已存在；已发布版本不得再次发布。版本/切源/恢复顺序仍按[发布流程](../20260713/plan-governance-distribution-setup.md)执行。
